CTF Write-Ups

Capture-the-flag challenges — solved & documented

Challenges from EURECOM's System Security lab and CTF practice. Write-ups are sanitized — techniques and lessons only, no live flags, hostnames or credentials.

Linux · pwn Privilege Escalation

SUID Binary & Relative-Path Hijack

A SUID-root helper executed a program via a relative path (execlp("./vuln", …)) while trusting the current working directory. The bundled overflow was a decoy — an exit(1) made it non-exploitable.

  • Audited the SUID binary and vulnerable source with ls -l, file and code review
  • Identified that execution resolved ./vuln from a writable directory
  • Planted a minimal setuid(0) + /bin/sh binary named vuln and ran the helper from there
  • Obtained a root shell and read the protected flag
SUIDPATH hijackGDBC / shellcode

Takeaway: SUID + relative paths + trusted CWD = privilege escalation. Mitigate with absolute paths, dropped privileges and bounded string ops (strncat).

Kernel · pwn 100 pts

Boot-Token Extraction via QEMU

The flag lived in a root-only file inside a QEMU VM. An init script derived it from the kernel command line, then locked /proc/cmdline — so the secret had to be recovered from outside the guest.

  • Traced /private back to an init script parsing token= from /proc/cmdline
  • Realised the flag was a kernel boot parameter passed to QEMU by a SUID launcher
  • On the host, located the QEMU PID and read /proc/<pid>/cmdline
  • Recovered the boot token — no kernel exploit required
QEMU/procboot paramsLinux internals

Takeaway: secrets passed on a process command line are world-readable via /proc; never put credentials in boot params or argv.

Network · forensics Multi-stage

Port Knocking + PCAP + SHA-256 PoW

A hidden service was gated behind a port-knocking sequence captured in a PCAP, followed by a cryptographic proof-of-work and a synchronized UDP scan to unlock the vault.

  • Analysed the capture in Wireshark; filtered SYNs with tcp.flags.syn==1 && tcp.flags.ack==0
  • Discovered the secret was encoded in the source-port sequence, not the destination
  • Extracted the unique sequence with tshark and replayed the knock with netcat
  • Solved a SHA-256 proof-of-work (digest starting with zero bytes), then a timed UDP scan to reveal the flag
WiresharktsharknetcatSHA-256 PoWPython

Takeaway: the authentication secret lived in packet metadata (source ports) — protocol-level forensics beats surface inspection.

Web · injection Web

SQL Injection — "The Safest Bank"

A web challenge exploiting an unsanitized query to bypass authentication and exfiltrate data from the backend database.

  • Probed input fields for injection points and error-based feedback
  • Crafted payloads to bypass login logic and enumerate the schema
  • Extracted the target data and documented the full chain
SQLiWeb securityAuth bypass

Takeaway: parameterize every query and validate input — string-built SQL is an open door.
